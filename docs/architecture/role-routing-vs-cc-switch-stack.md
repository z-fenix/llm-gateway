# 角色路由与 cc-switch Stack（聚合模式）架构对比

对照日期：2026-11-13。llm-gateway 基线 `47d8920`（本轮未改路由算法）；cc-switch 本地 `main`，revision `d300a120`。下述链接为仓库相对路径，参考项目路径以 `D:/workplace/project/tools/cc-switch/` 为根。

## 结论

**两者解决的是不同层的问题，不是同一种“多渠道路由”的两套 UI。**

- 本项目角色模式是 **逻辑模型/任务角色 → 服务端策略 → 具体渠道和模型**。客户端请求 `sonnet` 一类稳定标识，网关决定实际执行者，优先保障策略与可用性。
- cc-switch Stack 是 **多个供应商的模型目录 → 带供应商身份的客户端模型 ID → 单一供应商直达**。用户在客户端选择某个明确模型；失败时不能暗中换供应商或换模型。
- Stack 不是多模型并发、答案聚合、轮询负载均衡或自动故障转移池。cc-switch 自己的普通代理路由/故障转移是另外一条路径，不能与 Stack 混为一谈。

## 两条请求链

### llm-gateway：策略选择

```text
客户端 API key + 请求 model
  → 网关鉴权/配额
  → OpenAI / Anthropic / Responses 请求归一化
  → RAG / 请求安全扫描
  → role_patterns wildcard 匹配
  ├─ 有角色路由：已启用角色规则 → priority/weight 排序 → route_id 熔断放行
  │              → 依次尝试目标 channel + target_model → 末尾全局 fallback
  └─ 无角色规则：普通 enabled 渠道 → priority/weight 排序 → 每渠道 model_map
  → 协议适配 + 上游调用
  → 安全处理、渠道统计、请求日志、Token 配额 → 客户端协议响应
```

证据：
- `src-tauri/src/proxy/handlers.rs:188,306,359,389,397`：鉴权、安全扫描、角色识别、转发、扣配额；流式路径在 `:579` 后。
- `src-tauri/src/router/role.rs`：基于请求模型的匹配，不是基于自然语言内容的语义分类器。
- `src-tauri/src/db/repository.rs:715`：角色规则查询 `enabled=1`。
- `src-tauri/src/proxy/forwarder.rs:77-149`：真正生产候选构造；角色路由多目标，不是一个角色只能绑定一家。熔断按 route_id，追加 fallback。
- `src-tauri/src/router/dispatch.rs:45-145`：优先级分组、组内加权排列和普通模型映射。
- `src-tauri/src/proxy/forwarder.rs:170-218,285`：角色请求可遍历全部候选；普通请求最多 `retry_count + 1` 个候选；可故障转移错误与直接返回错误分开处理。

**实现边界须注意：** 当前 forwarder 给排序传固定 seed `1`，同配置产生确定顺序；虽然算法支持加权排列，不能据此承诺跨请求实现权重比例分流。普通 `plan_route` 分支也不会自动追加传入的 fallback。以上是现状分析，不在本轮悄悄更改调度语义。

### cc-switch：显式身份选择

```text
供应商配置 + Stack 成员清单
  → 分配永久供应商 key
  → 发布带 key 的模型目录 / 写客户端投影
  → 客户端 /model 明确选一个模型 ID
  → decode / resolve：模式、key、供应商存在、成员资格校验
  ├─ 命中：provider + upstream_model → 单供应商直达
  ├─ 带保留前缀但无效：明确报错，不回落默认
  └─ 普通无前缀 ID：默认供应商；Stack 开启时同样不故障转移
  → 正常协议适配 / 用量记录 → 返回
```

证据（cc-switch）：
- `src-tauri/src/mode/stack.rs:1-17`：模式语义与禁止静默回落。
- `:66-95`：永久 key 注册，移除/删除后也不把旧 key 分给新供应商。
- `:118,163`：编码/解码；Claude Code 示例 `ccs-claude-<key>--<model>`，Codex `ccs-<key>/<model>`；Desktop 为兼容选择器另用数字 ID，不可强行统一。
- `:692-740`：解析返回 `Plain / Hit / Miss`；模式关闭、未知 key、供应商删除、成员移除均与普通请求区分。
- `src-tauri/src/proxy/handler_context.rs:133-190,286-331`：显式目标仅一个供应商；普通无前缀模型在 Stack 模式下只走默认一家；关闭 failover，重试为 0，对应自动故障转移超时配置也停用。
- `src-tauri/src/proxy/forwarder.rs:566-576`：**显式 Stack 模型请求**不碰熔断/正在使用/代理路由统计，保持解析后的模型，不再套角色模型改写；用量日志仍按供应商记。
- `src-tauri/src/mode/controller.rs:1316`：成员变更与客户端投影的操作入口。

**细分边界：** `is_stack = stack.is_some()` 标识的是显式编码模型请求。无前缀的默认请求虽然也禁用故障转移，但不能仅凭“当前 UI 是 Stack”就宣称它完全绕过所有普通路由统计状态。

## 能力与状态对照

| 维度 | llm-gateway 角色模式 | cc-switch Stack |
| --- | --- | --- |
| 抽象对象 | sonnet / opus 等逻辑角色 | 供应商成员及其模型目录 |
| 最终路由决策者 | 网关管理员定义策略，服务端选择 | 用户/客户端选择编码 ID，服务端解析 |
| 同名模型隔离 | 角色隐藏具体供应商；普通 model_map 按渠道隔离 | key 编进 ID，同一个原始模型可同时属于不同供应商 |
| 模型改写 | 角色 target_model；普通路径每渠道 model_map | 编码 ID 解回上游名，显式目标不再按角色改写 |
| 多目标 | 一角色可配置多个候选 | 目录可有多家，但一次显式请求只绑定一家 |
| 优先级/权重 | 有；当前固定 seed 的确定排列，非已证明的比例分流 | 不用它在成员间挑选供应商 |
| 熔断 | 按角色 route_id 记录失败、半开、恢复 | 显式编码模型请求不读写路由熔断 |
| 失败语义 | 可重试/换候选/全局兜底，最终模型可能改变 | 保持选中供应商身份；错误返回，不静默改账单归属 |
| 失效标识 | 角色无规则时可进入普通调度路径 | 保留前缀失效必须报错，不能退回默认 |
| 默认/子代理 | 角色匹配由客户端请求 model 决定 | 默认供应商及客户端目录/别名投影参与后台和子代理选择 |
| 持久化 | SQLite：channels、role_patterns、role_routes、model_maps；plugin-store：全局设置；运行时熔断 | 供应商 DB + 设备 `live-state.json` 的 Stack 开关、成员、永久 key 登记簿 + 客户端配置投影 |
| 协议适配 | 独立于路由：四种 upstream_protocol | 也独立于显式身份路由；Stack 不等于协议转换器 |
| 日志/用量 | 网关统一 API key、Token 配额、安全日志与渠道统计 | 显式 Stack 不写路由状态，但照常写供应商用量日志 |
| 安全重点 | 凭据加密、网关鉴权/配额、请求响应安全扫描 | 身份命名空间、旧 ID 不重分配、失效 ID 不隐式换家；其他鉴权随各应用代理路径 |
| 客户端耦合 | 接入统一网关 endpoint 后主要依赖 model 字符串 | 强：模型 ID 规则、目录、窗口、默认别名随客户端形态投影 |

## 取舍与适用场景

### 保留角色模式作为本项目默认能力

适合团队希望“配置一次稳定角色，供应商可替换”，或要求按角色配置容灾与预算的场景。客户端不用认识每家供应商 ID；管理员可调整路由而不更新所有客户端。

代价是最终执行模型不完全由客户端锁定，回退必须通过日志、实际上游模型与渠道可观测；不能把“sonnet”标签当成供应商身份或等价质量保证。当前匹配是 model wildcard，中文“复杂任务”等是解释性标签，不代表自动理解问题难度。

### Stack 适合精确实验与显式供应商选择

适合对比两家同名模型、按供应商核账、用户要确保“就是我选的那家”或客户端原生 `/model` 工作流。永久 key 与错误即停止保护了身份稳定性。

代价是可用性责任移给用户/客户端：选中的一家失败不会被自动替代；目录与客户端设置必须同步，删除成员后旧会话的模型 ID 也必须有清晰错误。

## 本项目可以借鉴，但本轮不迁移

1. **候选来源可观测。** 真实模型获取、静态参考和手动模型必须区分。本轮已经修正这部分，不用内置候选冒充上游返回。
2. **阅读器与路由分层。** 提问—过程—回复来自本地 CLI 记录，不应拿网关请求日志伪造成 CLI 的执行轨迹。本轮保留结构化工具字段、折叠过程与关联日志入口。
3. **若未来加聚合，使用独立命名空间。** 显式 `provider/model` 与逻辑 `role` 不混用；先解析显式身份，再决定是否进入角色策略。无效显式 ID 必须错误，不能意外命中 wildcard 或 fallback。
4. **模式语义写进后端契约。** 显式直达模式不继承角色熔断/回退；统计保留原始选择和最终目标，不能为了 UI 方便让两种模式共享会悄悄换家的候选列表。
5. **先补路由观测与确定性说明，再谈替换。** 跨请求权重分流与角色请求实际落到哪个模型需要单独测试、设计和变更授权。本轮只交付架构比较，不改既有转发算法、费用语义或客户端配置。
