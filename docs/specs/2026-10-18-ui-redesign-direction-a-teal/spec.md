# Feature Specification: UI 重设计 · 方向 A（青碧信号）

**Change**: `2026-10-18-ui-redesign-direction-a-teal`

**Created**: 2026-10-18

**Status**: Draft

**Input**: User description: "优化本项目的 UI 设计"——经头脑风暴与视觉稿确认，选定方向 A（青碧信号）、做真暗色模式、全量页面范围。完整设计定稿见 `docs/superpowers/specs/2026-10-18-ui-redesign-design.md`。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 统一的视觉身份（P1）

用户打开网关应用的任何页面，看到同一套深青灰底、青碧强调色的界面：暗色模式为默认观感，界面里模型名、token 数、延迟等数据以等宽字体呈现且数字对齐；同类信息（状态徽章、统计数字、标签页）在所有页面长得一样。

**Why this priority**: 这是本次改造的核心价值——应用有可识别的身份，数据可读性提升；其余故事都建立在这套身份之上。

**Independent Test**: 逐页切换（概览/日志/渠道/设置等），核对配色、徽章、数字排版一致；切换明暗两态各过一遍。

**Acceptance Scenarios**:

1. **Given** 应用处于默认状态，**When** 用户打开任意页面，**Then** 界面使用统一的青碧信号配色，无页面各自为政的颜色。
2. **Given** 日志或概览页展示统计数字，**When** 数字变化，**Then** 数字列保持对齐（等宽/tabular），不跳动。
3. **Given** 同类元素（如 HTTP 状态徽章、风险徽章），**When** 出现在不同页面，**Then** 视觉样式与颜色语义一致。

---

### User Story 2 - 真暗色模式与主题切换（P1）

用户在设置页选择浅色/深色/跟随系统，界面即时切换；选择被记住，重启应用后仍生效；默认跟随系统。

**Why this priority**: 暗色是方向 A 的默认观感，也是现有死代码的清理前提；无持久化则三态切换形同虚设。

**Independent Test**: 依次切换三种主题并重启应用，观察即时生效与持久化。

**Acceptance Scenarios**:

1. **Given** 用户在设置页，**When** 选择"深色"，**Then** 整个应用（含侧边栏、弹窗、图表）立即切为暗色。
2. **Given** 主题为"跟随系统"，**When** 操作系统切换明暗，**Then** 应用随之切换。
3. **Given** 用户选择了"浅色"，**When** 关闭并重新打开应用，**Then** 仍为浅色。

---

### User Story 3 - 网关运行状态可见（P2）

用户在任意页面都能从顶栏看到网关是否在运行、监听哪个端口；网关未运行时状态点变红。

**Why this priority**: 网关状态是使用者的首要关注，但现在界面上无处可看；不依赖页面改造即可独立交付。

**Independent Test**: 启停网关，观察顶栏状态点与端口显示。

**Acceptance Scenarios**:

1. **Given** 网关已绑定端口，**When** 用户查看顶栏，**Then** 状态点为绿色并显示端口号。
2. **Given** 网关未绑定（启动失败/已停止），**When** 用户查看顶栏，**Then** 状态点为红色且不显示端口。

---

### User Story 4 - 页面信息密度与层级优化（P2）

日志页的表格成为主体：筛选和统计压缩为表格上方的一条统计带；概览页承接"Top 渠道/Top 密钥"榜单；渠道页用状态点标识启用/停用，停用渠道明显弱化；设置页按分组面板组织并新增"外观"分组。

**Why this priority**: 这是方向 A 落到具体页面的可见价值，但依赖故事 1 的令牌与组件先行。

**Independent Test**: 打开日志/概览/渠道/设置四页，对照视觉稿核对结构。

**Acceptance Scenarios**:

1. **Given** 日志页有数据，**When** 用户查看，**Then** 表格为主体，统计带在表格上方一行内呈现总调用/成功率/Token/费用。
2. **Given** 渠道列表中有停用渠道，**When** 用户查看，**Then** 停用渠道弱化显示并带停用标识，启用渠道有绿色状态点与延迟。
3. **Given** 设置页，**When** 用户查看，**Then** 看到分组面板布局，顶部为"外观"分组。

---

### User Story 5 - 无障碍与细节修正（P3）

键盘焦点可见；"减少动态效果"开启时状态点动画静止；修复渠道卡片从未生效的 hover 边框；删除所有不生效的 `dark:` 死代码。

**Why this priority**: 质量底线与积欠清理，不阻塞主要价值。

**Independent Test**: Tab 键遍历焦点；系统开启减少动效后观察状态点；代码检查 `dark:` 残留。

**Acceptance Scenarios**:

1. **Given** 用户用键盘导航，**When** 焦点落在按钮/输入框上，**Then** 出现可见的青碧色焦点环。
2. **Given** 系统开启"减少动态效果"，**When** 查看顶栏，**Then** 状态点不呼吸。

### Edge Cases

- 网关端口探测失败/未启动时，顶栏显示红色状态而非报错弹窗。
- 浅色模式下青碧强调色加深，保证文字对比度可读。
- 主题持久化不可用时（能力受限环境），主题三态仍当次会话内生效（内存态），不阻塞应用。
- 图表在两个主题下系列色均可辨识（风险 6 级、Token 4 系列）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为全部页面提供统一的设计令牌（配色、字体、圆角），界面代码 MUST NOT 出现散落的硬编码调色板色。
- **FR-002**: 系统 MUST 提供浅色与深色两套完整令牌，深色为默认观感。
- **FR-003**: 用户 MUST 能在设置页于浅色/深色/跟随系统三态间切换，切换即时生效。
- **FR-004**: 系统 MUST 持久化用户主题选择（持久化不可用时降级为会话内生效，见 Assumptions）。
- **FR-005**: 界面中的数据（模型名、渠道地址、密钥、token/延迟/费用、时间戳）MUST 以等宽字体呈现，数字列对齐。
- **FR-006**: 系统 MUST 提供统一的状态徽章组件语义（成功/警告/危险/信息/中性），全部页面的状态与风险标识 MUST 使用它。
- **FR-007**: 系统 MUST 提供统一的统计卡与分段标签页组件，替代各页面的重复实现（统计卡 ≥ 12 处、标签页 3 处）。
- **FR-008**: 侧边栏 MUST 按功能分组（运行/配置/能力/系统），入口与路由保持不变。
- **FR-009**: 顶栏 MUST 显示网关运行状态点与监听端口；状态随现有页面刷新机制更新。
- **FR-010**: 日志页 MUST 以表格为主体，统计信息压缩为单条统计带；Top 渠道/Top 密钥榜单 MUST 移至概览页。
- **FR-011**: 渠道页 MUST 以状态点 + 弱化样式区分启用/停用，MUST 常驻展示延迟。
- **FR-012**: 设置页 MUST 采用分组面板布局，"外观"分组置顶。
- **FR-013**: 界面 MUST 提供可见的键盘焦点环，并在系统"减少动态效果"时停止状态点动画。
- **FR-014**: 系统 MUST 修复渠道卡片 hover 边框失效问题，并删除不生效的 `dark:` 死代码。

### Key Entities *(include if feature involves data)*

- **设计令牌**：一组有名字的颜色/字体值（背景三阶、边框、正文三级、强调色、四个状态色），分浅色/深色两套取值；是所有界面样式的唯一来源。
- **主题偏好**：用户的三态选择（浅色/深色/跟随系统）及其实际生效结果。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户逐页切换时无需适应期——同类控件在所有页面外观一致（人工目检 14 页 × 2 主题无违例）。
- **SC-002**: 界面代码中硬编码调色板色为 0 处（自动检查）。
- **SC-003**: 用户切换主题后 1 秒内全应用生效，重启后选择保留。
- **SC-004**: 用户无需打开设置即可知道网关是否在运行及端口号。
- **SC-005**: 前端类型检查与单元测试全绿，后端代码零改动。
- **SC-006**: 键盘可完成所有页面可达性与操作（Tab 遍历无焦点丢失）。

## Assumptions

- Windows 为主平台；不打包网络字体，等宽字体依赖系统自带 Cascadia Code/Consolas。
- 主题持久化优先复用应用现有设置存储通道；若该通道前端不可授权，降级为浏览器本地存储（会话内体验一致，仅跨启动持久性受限），并在实现说明中记录。
- 页面路由、信息架构、后端接口均不变；本改造纯前端。
- UI 文案保持中文，风格与现有一致。

## Out of Scope

- 后端/Rust/Tauri 命令的任何改动。
- 新功能（除主题切换与顶栏状态外不新增能力）。
- 图表库更换、动效系统、浅色模式的独立美学设计（浅色由同一令牌系统派生）。
