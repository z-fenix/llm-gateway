## 浏览器验收

独立隔离 Chrome，入口 `http://127.0.0.1:5174/`，仅使用只读合成 Tauri bridge；真实生产 API 未注入假数据。

- 基础矩阵：9 个页面/状态 × 1440、1024、768、390px × 浅/深主题，共 72 项。
- 实际交互：渠道/状态/密钥/角色/风险/流式/会话来源菜单、获取模型与选中、主题、密钥管理、会话消息、自动刷新。
- 600px 矮窗：长渠道表单与七类管理弹窗/抽屉。
- 长会话：工具长输出、长标题、深层项目路径，桌面与手机两主题。
- 最终 **144 组通过、0 组失败**，无运行时异常、整页/主内容/弹窗横向溢出。最终矩阵另外检查模型键盘焦点、活动候选可见与回车选择。逐项结果在 [acceptance.json](acceptance.json)，机器验证摘要在 [verification.json](verification.json)。

首轮驱动中的 8 项断言失败保存在 [acceptance-initial.json](acceptance-initial.json)：4 项同步读取发生在 React 更新完成前，4 项定位了不存在的“应用”（实际是“保存渠道”）。修正等待与定位后重新执行，并未为驱动修改正确的产品行为。最终驱动也统一了密钥/渠道不同的提交按钮定位，并等待弹窗动画结束后测量几何位置。

复验脚本：`scripts/design-parity-round2.mjs`（Node 24；先启动 renderer、只读代理及调试端口 9226 的隔离 Chrome）。失败场景会返回非零退出码；`RETRY_ONLY=1` 可仅复验失败项和角色截图。
